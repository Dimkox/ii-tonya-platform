# Expert residency referrals traceability

Status: **disabled release candidate — staging and production are not
authorized**.

This matrix maps the approved requirements to the local implementation and its
executable verification. It is not activation evidence. All payment behavior
remains provider-neutral; no live provider, credential, or external call is
used.

## Evidence legend

- Implementation and test paths are repository-relative and concrete. The
  mandatory commands are wired through `package.json`, `.github/workflows/ci.yml`,
  and `.github/workflows/db-gate.yml`.
- The five named concurrency suites use count-first
  <code>pnpm test:repeat -- 3 ...</code>, exactly three runs. Ordinary suites run
  once.
- Bounded telemetry is defined in `packages/observability/src/metrics.ts`.
  `ii_tonya_expert_referral_lifecycle` accepts only finite `module`, `operation`,
  `outcome`, and `errorCode` values; entity IDs, codes, payment IDs, payloads,
  and free text are not labels. Expiry duration uses the same labels on
  `ii_tonya_expert_referral_operation_duration_ms`.
- Recovery actions below point to
  `docs/runbooks/expert-residency-referrals.md` or
  `docs/runbooks/expert-residency-referrals-rollback.md`. They preserve consumed
  codes, approvals, inboxes, settlements, refunds, debt, ledger facts, and
  applied migrations; schema recovery is forward-fix.
- Owners are the roles approved by the design: Product owner, Engineering,
  Security reviewer, and Release operator. Migration, financial, AI, staging,
  and production approvals remain separate gates below.
