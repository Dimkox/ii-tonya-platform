# Test Delivery 2026-09-07 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver an acceptance-ready test release of the ii-Tonya platform by 2026-09-07, with Releases C-F implemented behind independently reversible flags and every unavailable external provider represented by a tested fail-closed adapter.

**Architecture:** PostgreSQL remains the authority for lifecycle jobs, bookings, waitlists, commercial ledgers, events, inboxes, outboxes, and audit facts. API routes invoke application services; bounded workers claim PostgreSQL rows with `FOR UPDATE SKIP LOCKED`; every user-visible Telegram message enters the existing ordered `telegram.send_text.v1` outbox. Provider adapters never become business-state authorities and stay disabled until their authenticated test contracts pass.

**Tech Stack:** TypeScript, Node.js 24, pnpm 11.9.0, PostgreSQL 15+, Drizzle ORM, Fastify, Vitest, native API/worker release bundle, Claw CI.

**Spec:** `docs/superpowers/specs/2026-08-28-free-client-hybrid-platform-v2-design.md`

## Global Constraints

- Test acceptance deadline is 2026-09-07; production activation is outside this plan.
- Ordinary-client platform access remains free under `free_client_v2`.
- Expert tariffs remain `3900/5900/9990 RUB`, 30 days, with the existing 30% expert-credit ceiling.
- Future package validity is 30 days and future coupon validity is 45 days.
- `тест эксперт` consumes no more than 100 free visible messages; deterministic warm-up remains outside Selarti.
- The client sees one Telegram account and one ordered dialogue.
- Selarti handles only allowlisted complex dialogue and cannot mutate authoritative state.
- Coupon, Planerka, Selarti, YooKassa, MAX, and live Telegram capabilities remain independently default-off until their own test evidence passes.
- Secret values remain only in ignored mode-`600` environment files and never enter Git, logs, fixtures, evidence, or review reports.
- Existing Yandex Metrika counter and approved static scripts must survive every landing rebuild.
- Schema changes are forward-only versioned migrations; rollback disables flags and uses forward repair rather than destructive down-migrations.

## Definition of test delivery

The deadline is met when the exact test-release SHA has passed focused tests, aggregate
verification, Claw CI, Database Gate, independent review, native artifact verification,
test-host smoke/E2E, and rollback rehearsal. Missing external API contracts do not block
test delivery when the corresponding adapter is fail-closed, the feature is visibly
disabled, and contract fixtures prove the local boundary; they do block claims that the
external provider itself is operational.
