[evidence](../../_bmad-output/specs/spec-owner-update-2026-09-16/evidence/DEC-PLT-004-rule.md);

## 0. Инварианты (нарушение = дефект)

1. **Единственный персист оператора — PostgreSQL на серверах в РФ** (DEC‑PLT‑004 §9). Нет операторского
   хранения ПД вне него: Google Sheets/Make — не персист ПД (только обезличенные проекции либо выкл);
   Telegram — транспорт без задержки ПД; `object_store`/бэкапы — РФ.
2. **Специальные категории ст.10 152‑ФЗ и ПД третьих лиц не хранятся никогда.** Их наличие может
   учитываться **только как переходящий in‑session сигнал** (как микро‑чекапы), без постоянной колонки и
   без передачи эксперту. Запрещённые колонки: `birth_date/date_of_birth/age/gender/sex/children/
grandchildren/kids/marital/family_status/social_status/income/living_standard/health/diagnosis` → 0.
3. **Каждая цель — отдельный проверяемый факт согласия** со своим `consent_type`; «начало диалога/акцепт»
   не покрывает ни передачу эксперту, ни маркетинг, ни cookies‑аналитику (C005 юридически недостаточно).
4. **Отзыв останавливает обработку, но не аннулирует учётный факт** (брони/платежи держатся на договоре/ФЗ).

## 3. Эксперт/резидент и посетитель (B088)

**Эксперт:** ФИО/наименование/ИНН‑ОГРНИП, контакты, квалификация (реквизиты+результат проверки+digest;
**копии документов не хранятся**), опыт, услуги/цены, адрес (публично город+формат), ссылки, промокоды —
Д/С. Платёжные: расчётный счёт/IBAN + `provider_token` ЮKassa; **PAN/CVC/срок — никогда**.
**Посетитель:** поля формы ≤12 мес; IP **усечённый**; браузер/страницы/время — агрегат после opt‑in;
cookies necessary ≤30 дн.; analytics ≤6 мес после `cookies_analytics`; **маркетинг‑пиксели не ставятся**.

## 4. Получатели и юрисдикции (DEC‑PLT‑004 §4/§9)

- **Эксперт** (названный) — предоставление после `expert_handoff`; объём ≤{имя, канал, запрос}; хранение ≤30 дн. после визита, удаление по требованию.
- **ЮKassa** (РФ) — транзакция; без PAN. **Planerka/Selarti** — только после доказательства РФ‑юрисдикции/хостинга; иначе минимум/отключение.
- **Google Sheets / Make** — не канал ПД (обезличенная проекция или выкл). **Telegram** — транспорт (ФИО/телефон/e‑mail/`expert_note` в чаты, вкл. admin/safety, запрещены). **LLM** — только РФ‑модель или обезличенный промпт; запрет обучения.
- **Госорганы** — по закону (п.2 ч.1 ст.6), журнал.

## 5. Retention (DEC‑PLT‑004 §5)

Идентификация — 24 мес неактивности → псевдонимизация; согласия/аудит — +3 года после удаления;
профиль/`expert_note` — ≤24 мес, при отзыве немедленно; брони/платежи — 5 лет (115‑ФЗ/НК/431‑У);
платёжные артефакты ЮKassa ≤400 дн., unbound 0; формы ≤12 мес; cookies analytics ≤6 мес/necessary ≤30 дн.;
IP ≤6 мес; медиа ≤12 мес; backup 35 дн. с receipt. Спецкатегории/дети/семейное/соцстатус/ДР/пол/возраст/здоровье — **создание запрещено**.

## 6. Существующие данные и уже оплаченное (DEC‑PLT‑004 §6; T0 = дата в `.memlog.md`)

- **T0‑A** незаконные категории (дети/семейное/соцстатус/ДР/пол/возраст/здоровье в персисте) — **удаление**, T0+14 / backup‑cycle T0+49.
- **T0‑B** необязательное по «начало диалога» — кампания «пересогласовать или удаление», **60 дней**, молчание = отказ, жёсткое удаление T0+61.
- **T0‑C** уже оплаченные/действующие — **grandfather** (п.5 ч.1 ст.6); с T0 прекращаются промо/рассылки/чекапы/аналитика и **все новые** передачи без `expert_handoff` (T0‑C2).
- **T0‑D** старые ряды `consents` — не мутируются, помечаются `superseded_versions`.

## 7. Проверка (реализует `consent.test.ts` + checks DEC‑PLT‑004 §7)

- Отсутствие/отзыв `expert_handoff` ⇒ в expert‑view нет имени/заметки/контактов (минимальный `{«Клиент», слот, формат, meeting_url}`); отзыв ⇒ мгновенно (тот же запрос).
- Чужой субъект (эксперт/менеджер/клиент) не читает профиль; deny **не различает** «нет записи» и «нет права» (без оракула существования).
- 0 запрещённых колонок во всех схемах/вью/проекциях; экспертный payload ≤3 поля ПД; выборка «передача без предшествующего granted» = 0.
- cookies не приравниваются к согласию передачи; «начав диалог/используя сайт соглашаетесь» — 0 входов в публичных текстах.
