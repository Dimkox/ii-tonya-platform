# Prod enable checklist (client MVP + integrations)

Шаблон: `deploy/runtime.env.example`, блок `FULL ENABLE PROFILE`. Значения — только плейсхолдеры;
реальные секреты берутся из хранилища секретов на хосте и в репозиторий не попадают.
Каждый шаг: поменять флаги → перезапуск api/worker → `/health/*` зелёный → только потом следующий.

## Ограничения до старта

- `scripts/validate-runtime-env.sh` (release mode) пока требует `false` для `SELARTI_ENABLED`,
  `TELEGRAM_ENABLED`, `PAYMENTS_ENABLED`, `EXPERT_REFERRAL_ENABLED`, `EXPERT_RESIDENCY_BILLING_ENABLED`,
  `EXPERT_TELEGRAM_QUERIES_ENABLED`, а также `PAYMENT_PROVIDER=disabled`. Файл закреплён хешем в
  `tests/repo/scope-boundary.test.ts`; до живого включения этих шагов гейт надо обновить отдельным PR.
- `LIFECYCLE_CHECKUPS_ENABLED`, `LIFECYCLE_FEEDBACK_ENABLED`, `LIFECYCLE_COUPON_NOTICES_ENABLED`
  схема отвергает (нет authority) — оставить `false`.
- Заперты схемой: `LLM_ENABLED`, `INTENT_MODEL_ENABLED`, `MAKE_PROJECTION_ENABLED`,
  `GOOGLE_SHEETS_PROJECTION_ENABLED`, `MINOR_ONBOARDING_ENABLED`, `LLM_PROVIDER=disabled`.
- `PLANERKA_ENABLED` удалён из схемы (игнорируется).

## Предусловия (до шага 1)

- `TELEGRAM_BOT_TOKEN` должен быть задан до шага 2: при `CLIENT_SESSION_ENABLED=true` `createDefaultLifecycle` строит верификатор сессии из этого токена (`assertClientCapabilityPreflight`), иначе старт падает с `Client session verifier capability is required`. Флаг `TELEGRAM_ENABLED` при этом может оставаться `false`.
- Шаги 6 и 8 требуют живых capability в композиции (`resolveIntegrationBoundaries`): без них старт падает с `telegram_callback_capability_required` / `selarti_capability_required`. Живые `LiveSelartiAdapter` и `createTelegramCallbackService` компонуются в `createDefaultLifecycle` только после PR #139 — до его мержа шаги 6 и 8 не включать. Это требование к коду, а не к секретам (см. `docs/wiki/Composition-and-Flags.md`).
- Шаг 10 требует keyring `EXPERT_REFERRAL_HMAC_KEYS_JSON` (JSON `{ "<version>": "<base64url без паддинга, ≥32 байт>", ... }`, содержит текущую `EXPERT_REFERRAL_HMAC_KEY_VERSION` и сохранённые прошлые версии), а `EXPERT_REFERRAL_HMAC_KEY_REF=env://EXPERT_REFERRAL_HMAC_KEYS_JSON`. Без него `EnvironmentExpertCodeSecretResolver` бросает `expert_referral_key_unavailable`. Генерировать на сервере (`openssl rand 32 | basenc --base64url | tr -d =`), не печатая.
