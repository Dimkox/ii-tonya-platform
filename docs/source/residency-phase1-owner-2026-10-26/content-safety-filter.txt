# 📋 ТЗ ДЛЯ GETZILLA: МОДУЛЬ АВТО-МОДЕРАЦИИ (AI GUARDRAILS)
## Модуль: `content_safety_filter` | Статус: КРИТИЧНО / БЛОКИРУЮЩИЙ

**Контекст:**
Перед отправкой карточки резидента менеджеру или публикацией обновлений, система должна провести автоматическую проверку текстовых полей (`bio_detailed`, `service_items.description_full`, `tags_array`) на наличие запрещенных формулировок. Это защищает платформу от юридических рисков (нарушение 152-ФЗ, законов о рекламе медицинских услуг) и репутационных потерь.

**Цель:** Реализовать жесткий фильтр стоп-слов и паттернов. При обнаружении нарушения бот блокирует сохранение/отправку и требует исправления текста пользователем.

---

## 1. АРХИТЕКТУРА ДАННЫХ (SCHEMA CHANGES)

### Таблица `forbidden_patterns` (Новая)
| Поле | Тип | Описание | Примечание |
| :--- | :--- | :--- | :--- |
| `id` | UUID | PK | - |
| `pattern_regex` | STRING | Регулярное выражение для поиска | Case-insensitive |
| `category` | ENUM | `MEDICAL_CLAIM`, `FINANCIAL_GUARANTEE`, `POLITICAL_RELIGIOUS`, `HATE_SPEECH`, `SPAM_SCAM` | Для классификации ошибки |
| `severity_level` | ENUM | `BLOCKER` (не сохранить), `WARNING` (сохранить, но подсветить менеджеру) | DEFAULT BLOCKER |
| `error_message_template` | TEXT | Текст подсказки для пользователя | С плейсхолдерами `{MATCHED_WORD}` |
| `is_active` | BOOLEAN | Флаг использования | DEFAULT TRUE |

---

## 2. СОДЕРЖАНИЕ ФИЛЬТРА (SEED DATA)

Разработчик должен предзаполнить таблицу следующими правилами. Паттерны составлены так, чтобы ловить как прямые утверждения, так и косвенные обещания результата.

### Группа А: Медицинские гарантии и Диагностика (Без лицензии)
*Категория:* `MEDICAL_CLAIM` | *Severity:* `BLOCKER`

1.  **Лечение заболеваний:**
    *   Regex: `\b(вылеч[ию]|избавлю\s+от\s+(рак|диабет|гепатит|ВИЧ|СПИД|туберкулез|онкология))\b`
    *   Message: *«Пожалуйста, уберите обещания вылечить серьезные заболевания. Наша платформа не является медицинским учреждением.»*
2.  **Гарантия результата в терапии:**
    *   Regex: `\b(гарантирую\s+(результат|исцеление|излечение)|100%\s+эффект|поможет\s+всегда)\b`
    *   Message: *«Избегайте категоричных гарантий результата. Используйте формулировки "способствует", "помогает работать с".»*
3.  **Диагностика без врача:**
    *   Regex: `\b(поставлю\s+диагноз|назначу\s+лекарства|пропишу\s+таблетки|медикаментозное\s+лечение)\b`
    *   Message: *«Вы не имеете права ставить диагнозы или назначать медикаменты без медицинской лицензии. Удалите эти пункты.»*
4.  **Сравнение с медициной:**
    *   Regex: `\b(лучше\s+чем\s+врач|замена\s+лекарств|отмена\s+препаратов)\b`
    *   Message: *«Не позиционируйте свои услуги как замену официальной медицине.»*

### Группа Б: Финансовые обещания и Инвестиции
*Категория:* `FINANCIAL_GUARANTEE` | *Severity:* `BLOCKER`

1.  **Быстрый заработок:**
    *   Regex: `\b(заработок\s+\d+[км]\s+в\s+(день|неделю|месяц)|легкие\s+деньги|секрет\s+богатства)\b`
    *   Message: *«Обещания быстрого обогащения запрещены политикой сервиса.»*
2.  **Инвестиционные гарантии:**
    *   Regex: `\b(доходность\s+\d+%|гарантированный\s+доход|безрисковые\s+инвестиции|крипто\s+сигналы\s+100%)\b`
    *   Message: *«Финансовые услуги должны сопровождаться дисклеймером о рисках. Прямые гарантии дохода недопустимы.»*
3.  **Мошенничество/Схемы:**
    *   Regex: `\b(схема\s+обогащения|пирамида|MLM\s+структура|сетевой\s+маркетинг\s+гарантия)\b`
    *   Message: *«Проекты сетевого маркетинга с признаками пирамид не размещаются.»*

### Группа В: Религия, Политика и Эзотерика (Ограничения)
*Категория:* `POLITICAL_RELIGIOUS` | *Severity:* `WARNING` (Менеджер решает вручную)

1.  **Агрессивная пропаганда:**
    *   Regex: `\b(только\s+мы\s+спасем|все\s+остальные\s+во\nlаке|религиозная\s+истина\s+единственнaя)\b`
    *   Message: *«Проверьте тон изложения. Избегайте противопоставления себя другим группам.»*
2.  **Политические призывы:**
    *   Regex: `\b(голосуйте\s+за|бойкот|санкции\s+против|революция)\b`
    *   Message: *«Сервис нейтрален к политической повестке. Уберите прямые призывы.»*
3.  **Магические ритуалы воздействия:**
    *   Regex: `\b(приворот|отворот|порча|сглаз\s+снятие|воздействие\s+на\s+волю)\b`
    *   Message: *«Практики, направленные на принуждение воли других людей, требуют особой модерации. Опишите метод мягче или подготовьтесь к звонку менеджера.»*

### Группа Г: Язык вражды, Агрессия и Спам
*Категория:* `HATE_SPEECH` / `SPAM_SCAM` | *Severity:* `BLOCKER`

1.  **Оскорбления и дискриминация:**
    *   Regex: `\b(жиды|пидорасы|шлюхи|уроды|деграданты|[расовые оскорбления])\b` *(Список расширяется)*
    *   Message: *«Использование оскорбительной лексики запрещено.»*
2.  **Спам-ссылки:**
    *   Regex: `(bit\.ly|tinyurl|cut\.cc|t\.me/joinchat/[A-Za-z0-9_-]+(?!\.ii_tonya))`
    *   Message: *«Разрешены только ссылки на ваши официальные соцсети. Сокращатели ссылок и приглашения в чужие группы запрещены.»*
3.  **Капслок (крик):**
    *   Logic: Если > 50% текста в верхнем регистре -> Warning.
    *   Message: *«Пожалуйста, используйте обычный регистр. КАПС воспринимается как крик.»*

## 3. ЛОГИКА ПРИМЕНЕНИЯ (IMPLEMENTATION LOGIC)

### Шаг 1. Проверка при вводе (Real-time Validation)
В интерфейсе бота (`@ii_tonya_expert_bot`) и админке:
1.  Пользователь вводит текст в поле `description` или `bio`.
2.  При потере фокуса поля (blur event) или нажатии кнопки «Сохранить»:
    *   Вызывается функция `check_content_safety(text)`.
    *   Функция проходит по всем активным паттернам из `forbidden_patterns`.
3.  **Если найдено совпадение с Severity = BLOCKER:**
    *   Сохранение блокируется.
    *   Бот/Интерфейс выдает ошибку: *«⛔ Обнаружено нарушение: {error_message_template}. Пожалуйста, исправьте текст перед продолжением.»*
    *   Подсвечивается конкретное слово/фраза в тексте (если возможно).
4.  **Если найдено совпадение с Severity = WARNING:**
    *   Сохранение разрешено.
    *   В карточку менеджера добавляется флаг `HAS_SENSITIVE_CONTENT = True` + список найденных триггеров. Менеджер обязан прочитать этот фрагмент лично.

### Шаг 2. Проверка тегов (Tags Filter)
При выборе хэштегов или вводе своих:
1.  Система проверяет ввод против списка `forbidden_tags` (например, `#лечениерака`, `#быстрые_деньги`).
2.  Запрещенные теги удаляются автоматически с уведомлением: *«Тег #... удален как несоответствующий правилам платформы.»*

### Шаг 3. Логирование инцидентов
Каждое срабатывание фильтра записывается в таблицу `security_logs`:
*   `user_id`
*   `field_name`
*   `matched_pattern_id`
*   `timestamp`
*   `action_taken` (Blocked/Warned)

Это поможет анализировать, какие категории экспертов чаще всего пытаются нарушить правила, и корректировать промпты онбординга.

---

## 4. ИНСТРУКЦИЯ ДЛЯ ПОЛЬЗОВАТЕЛЯ (UX COPYWRITING)

Чтобы не раздражать честных экспертов, сообщения об ошибках должны быть конструктивными:

*   ❌ Плохо: «Ошибка. Запрещенное слово.'»
*   ✅ Хорошо: «Мы заметили фразу "{MATCHED_WORD}". Чтобы избежать недоразумений с клиентами и соответствовать законам РФ, пожалуйста, замените её на более мягкую формулировку, например: "работаю с темой..." или "помогаю улучшить состояние..."»

---

## 5. ЧЕК-ЛИСТ ПРИЕМКИ (ACCEPTANCE CRITERIA)

- [ ] Таблица `forbidden_patterns` заполнена минимум 20 ключевыми правилами.
- [ ] Функция `check_content_safety` интегрирована в процесс сохранения профиля и услуг.
- [ ] При попытке сохранить текст с фразой «вылечу рак» процесс блокируется, пользователь получает понятную ошибку.
- [ ] При вводе тега `#приворот` система показывает предупреждение (Warning) и помечает карточку для ручной проверки.
- [ ] Все инциденты логируются в `security_logs`.
- [ ] Админ может добавлять новые паттерны через UI (или SQL seed скрипт) без перезапуска сервиса.

**Разработчик, реализуй этот модуль в первую очередь после стабилизации БД. Без него запуск сбора данных небезопасен.**
