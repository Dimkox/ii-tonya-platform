# 📋 ТЗ ДЛЯ GETZILLA: БАЗА ХЭШТЕГОВ И СЕМАНТИЧЕСКИХ ТЕГОВ (HASHTAXONOMY V2.0)
## Модуль: `semantic_matching_engine` | Статус: УТВЕРЖДЕНО К ВНЕДРЕНИЮ

**Контекст:**
Для обеспечения максимального качества мэтча между запросами клиентов и услугами резидентов необходимо внедрить расширенную базу тегов. База включает не только классические хэштеги, но и ключевые фразы, синонимы проблемных зон и методик. Это позволит алгоритму распознавать намерение клиента даже при использовании им сленга или общих формулировок.

**Цель:** Загрузить полную структуру данных в таблицу `hashtags_db` и настроить алгоритм рекомендации тегов для бота онбординга.

---

## 1. АРХИТЕКТУРА ДАННЫХ (SCHEMA CHANGES)

### Таблица `hashtags_db` (Обновленная/Расширенная)
| Поле | Тип | Описание | Примечание |
| :--- | :--- | :--- | :--- |
| `id` | UUID | PK | - |
| `parent_category` | STRING | Основная ниша (Психология, Тело, Дух...) | Для группировки в UI |
| `sub_category` | STRING | Подниша (Тревога, Отношения, Йога...) | Фильтрация |
| `tag_value` | STRING | Сам тег/фраза без символа # (например, "тревожность") | Индекс поиска |
| `display_label` | STRING | Как отображать пользователю (с # или текстом) | UX |
| `synonyms_json` | JSONB | Массив синонимов и частотных запросов клиентов | `[{"term": "паника"}, {"term": "не могу уснуть"}]` |
| `weight_score` | INT | Приоритет тега (1-10). Высокий вес = чаще предлагается | Алгоритм ранжирования |
| `is_active` | BOOLEAN | Флаг использования | DEFAULT TRUE |

---

## 3. ЛОГИКА РЕКОМЕНДАЦИИ (ALGORITHM SPECIFICATION)

При заполнении профиля резидентом система должна выполнять следующие шаги для формирования списка тегов:

1.  **Tokenization & NLP Analysis:**
    *   Разбить текст услуги (`description_full`) и био (`bio_detailed`) на токены.
    *   Определить основные сущности (Person, Location, Method, Problem).

2.  **Matching Strategy:**
    *   **Exact Match:** Если в тексте есть слово "тревога", предложить тег `#тревожность`.
    *   **Synonym Match:** Если в тексте есть "ПА" или "паника", предложить тег `#панические_атаки` (через проверку поля `synonyms_json`).
    *   **Category Inference:** Если указана методика "КПТ", автоматически предложить смежные проблемы, которые она решает (`#тревожность`, `#депрессия`, `#страхи`), так как это стандартный набор компетенций КПТ-терапевта.
    *   **Format Tagging:** Если указан формат "Онлайн", добавить системный тег `#онлайн`. Если адрес — тег `#офлайн_{City}`.

3.  **Ranking & Display:**
    *   Отсортировать предложенные теги по `weight_score` (убыванию).
    *   Показать топ-10 наиболее релевантных тегов как выбранные по умолчанию (checkbox checked).
    *   Остальные подходящие теги показать в списке ниже (unchecked, но доступны для выбора).
    *   Добавить поле **"Другое"** для ввода собственных тегов пользователем.

4.  **Validation:**
    *   Запретить ввод тегов из стоп-листа (политика, религия, медицинские гарантии).
    *   Ограничить количество тегов одним профилем (например, макс. 20 тегов), чтобы не размывать SEO-вес.
