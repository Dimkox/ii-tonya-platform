## Review priorities

Inspect rejected request transaction boundaries: incident/outcome must survive while
content does not. A replay must remain rejected without extra incidents. Direct SQL
rejection can roll back the SQL transaction; application rejection must deliberately
commit its minimal outcome. No raw rejected text in security telemetry or incidents.

Append-only history must coexist with an actual usable owner correction flow.
Checking every historical answer would permanently trap users after a policy update.
Effective content and selected tag values must bind the exact approved proof, with
current policy locking preventing approval/publication races. Manager warnings require
reviewable source fields and explicit current acknowledgment under normal authority.

Failed candidate policy activation must preserve the previous active policy. Missing
or corrupt active policy denies gated work. Unsupported syntax and oversized inputs
must fail within explicit budgets rather than reach a backtracking engine. Inspect
normal composition, imports/manual fallback, privacy deletion and actual publication
entrypoints, including the latest replacement SQL functions rather than old copies.

The final three-layer review is read-only. Concrete accepted findings go to the same
implementer in one bounded corrective batch, preserving good code. No routine approval,
re-derivation or quota loop. Final local gates and push evidence will be recorded after
implementation and independent review; hosted CI does not exist in this repository.
