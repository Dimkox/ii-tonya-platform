## Reproduction and limits

The archived `run-focused.mjs.gz` and `run-files.mjs.gz` load credentials from the protected task configuration into child environment memory and sanitize captured output. They never print the secret, place it in argv, or start another cluster. The reconstruction helper performs full hand-authored SQL replay in a disposable database and introspects into a new empty temporary directory; it does not run `drizzle-kit generate`.

Browser fixtures are synthetic actual API response bodies from the PG witness. The browser helper replays them through the production client/view code over a local server. It proves rendering and client clearing, while the PG/HTTP witness proves actual authentication/session checks. It is not a live production-browser test. The manager and protected choices screenshots are included separately.

The online-due fixture deliberately uses a direct synthetic short lead to exercise the 30-minute disclosure window. Actual protected discovery retains its existing 24-hour booking lead. Historical diagnostic logs do not all have separate exact argv or intermediate uncommitted source snapshots; the manifest explicitly marks missing command metadata instead of reconstructing an unsupported claim. Final commands, source hashes, log summaries and available timing/result records are preserved.

Recovery and rollout restrictions are in `docs/operations/resident-native-scheduling.md`. Once native bookings exist, rollback must retain source-bound booking/read/logistics support and immutable delivery facts; do not drop tables, invent provider success or reset uncertain sends.
