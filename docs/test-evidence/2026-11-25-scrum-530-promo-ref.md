# SCRUM-530. Проверка промобота и REF, 25 ноября 2026

## Что проверено на ПРОДе

Главная страница, `/health/live` и `/health/ready` ответили HTTP 200. Проверка готовности подтвердила PostgreSQL, миграции, аренду воркера и адаптеры. Публичный экспертный маршрут тарифов ответил HTTP 404. Маркер сайта показал `98a8fc4b933e3807323d80410e7c0b212021b598`. Версия работающего API из этих ответов неизвестна. [Готовность](https://ii-tonya.ru/health/ready) · [Версия сайта](https://ii-tonya.ru/SOURCE_SHA)

Публичные страницы промобота и канала открылись по HTTPS с профилями настольного и мобильного браузеров. В обоих случаях Telegram сохранил параметр `start=REF_000000000000` в ссылке открытия приложения. Это тестовый код. Ручной проход внутри приложений Telegram и сканирование QR из окончательного PDF ещё предстоят. [Промобот](https://t.me/ii_tonya_expert_promo_bot) · [Канал](https://t.me/ii_tonya_experts_promo)

## Основание работы

Базовый коммит GitHub — `07b771091376a19392565c51eea6a1d7a5b05707`. На нём три удалённые проверки завершились ошибкой. При воспроизведении на PostgreSQL до правки таймер вернул только пользователя и чат, хотя участник имел личный код и одного зачтённого гостя. При переходе по выданному ботом публичному REF также воспроизвелись ошибки на этапах ожидания согласия и регистрации. [GitHub и проверки базы](https://github.com/Dimkox/ii-tonya-platform/commit/07b771091376a19392565c51eea6a1d7a5b05707/checks)

## Условия выпуска и восстановления

Итоговый целевой прогон Vitest прошёл 315 из 315 тестов в 23 файлах. В него вошли таймеры, ответы промобота, маршруты HTTP, файлы подарка, FAQ, реестр команд и проверки миграций. Отдельно прошли 23 теста регистрации в `phase1-promo`, четыре теста квитанций и конкурентного отказа, а также два сквозных сценария выдачи PDF и восстановления регистрации при недействительном коде. Проверки проводились на локальной ветке. CI и Database Gate для нового коммита требуют публикации ветки.

Миграция 0092 добавляет пару полей для времени подтверждения текста и идентификатора сообщения Telegram. Старый `message6_sent_at` остаётся отметкой попытки. При неизвестном исходе резервирование сохраняется. Автоматической повторной отправки и восстановления квитанции по одному времени попытки нет.

Для будущей согласованной выкладки остановить прежний обработчик промотаймеров до миграции и запуска нового. Во время отката остановить обработчик таймеров. Старый воркер считает пять суток от попытки и при совместной работе нарушит правило. Не очищать маркеры отправки, строки доставки или согласия. Для спорных отправок потребуется отдельная сверка с подтверждением Telegram.

Для приёмки финального гайда остаётся проверить файл, баннер и QR-код, затем получить гайд через промобота на телефоне и компьютере.
